# 🥐 빵덕후 레벨업

부산 빵집을 찾아다니고, 리뷰(모험 일지)를 남기고, 레벨을 올리는 **빵집 탐험 RPG 컨셉의 빵지순례 커뮤니티** 웹사이트예요.
해운대 · 서면 · 남포동 · 광안리 · 동래의 실제 빵집 정보를 카카오 지도 SDK의 장소 검색으로 불러와요.

웹/UIUX 디자이너 포트폴리오로 만든 프로젝트예요. 기획 · 디자인 시스템 · 화면 · 구현을 한 사람이 진행했어요.

- 데모: https://yrkim2605-wq.github.io/my-first-website/my-bakery-review/
- 별도 가입 없이 닉네임만 정하면 대부분의 기능을 써볼 수 있어요 (아래 "데이터 저장 방식" 참고).

## 컨셉과 디자인

"빵집 탐험 = 모험"이라는 한 문장으로 모든 화면을 묶었어요.

| 서비스 요소 | RPG 표현 |
|---|---|
| 첫 화면 | 모험 시작 화면 (타이틀 + 빵 기사) |
| 빵집 지도 | 빵지순례 월드맵 |
| 추천 빵집 | 오늘의 추천 퀘스트 |
| 레벨 · EXP | 모험가 길드 (빵린이 → 빵탐험가 → 빵전문가 → 빵마스터 → 빵덕후) |
| 내 리뷰 | 모험 일지 |
| 마이페이지 | 내 모험가 상태창 (퀘스트 · 배지 · 빵집 도감) |
| 랭킹 | 명예의 전당 |
| 커뮤니티 | 모험가 광장 |

- **색**: 와인 · 크림 · 세이지 · 나무색. 글자 대비는 `supabase/tests/color-contrast.test.mjs`로 검사해요 (WCAG AA 기준).
- **글꼴**: 본문 Pretendard, 제목 Noto Serif KR, 장식 문구 Gaegu.
- **일러스트**: 직접 만든 빵 기사 캐릭터와 장식 요소를 투명 배경 WebP로 분리해서 써요. 글자가 박힌 그림은 피하고, 글자는 HTML 텍스트로 두었어요.
- **반응형**: PC 1366px, 모바일 390px, 가장 좁은 320px까지 가로 스크롤 없이 확인해요. 터치 영역은 44px 이상으로 맞추고, 모바일에서는 장식 일러스트를 줄이거나 숨겨서 내용을 가리지 않아요.
- **움직임**: "움직임 줄이기" 설정을 켠 사용자에게는 떠다니는 장식 애니메이션이 멈춰요.

## 주요 기능

| 페이지 | 내용 |
|---|---|
| **홈** | 히어로 · 빵집 검색과 지역 필터 · 월드맵 · 오늘의 추천 퀘스트 · 모험가 길드 · 인기 일지 · 전체 빵집 (더 보기) |
| **빵집 상세** | 빵집 정보, 평균 별점, 모험 일지 목록, 일지 쓰기 · 고쳐 쓰기 · 지우기, 찜하기, 다녀왔어요 체크 |
| **커뮤니티** | 카테고리 · 정렬, 글 상세, 댓글 · 답글 · 좋아요 |
| **내 모험가 상태창** | 레벨 · EXP, 퀘스트 보드, 획득 배지, 빵집 도감, 내 모험 일지, 찜한 빵집 |
| **명예의 전당** | EXP 순위, 이번 달 리뷰왕, 리뷰 많은 빵집, 좋아요 많은 글 |
| **로그인 · 가입** | 로컬 프로필(닉네임) 또는 이메일 계정 |

### 성장 규칙 (`src/constants/gameRules.js`)

- 리뷰 1개 +30 EXP, 사진을 붙이면 +10 EXP 추가
- 퀘스트: 첫 모험 일지 +20, 서로 다른 빵집 3곳 +30, 서로 다른 지역 3곳 +50
- 레벨 기준: 0 / 60 / 180 / 400 / 800 EXP
- EXP는 저장된 리뷰에서 매번 계산해요. 새로고침이나 같은 리뷰로 중복 지급이 안 되고, 리뷰를 지우면 그 EXP도 사라져요.
- 한 빵집에는 리뷰를 1개만 남길 수 있고(고쳐 쓰기는 가능), 계정 모드는 하루 EXP 상한(100)을 서버가 정해요.

### 빵집 사진 정책

- 빵집 사진은 **실제 리뷰 사진만** 써요. 사진이 없으면 빵 기사 플레이스홀더(카메라 · 지도 · 돋보기 · 책)를 보여주고, 관련 없는 스톡 사진은 쓰지 않아요.
- 업로드는 JPG · PNG · WebP, 10MB 이하만 받고 파일 내용으로 형식을 확인한 뒤 800px JPEG로 줄여요.
- 리뷰 사진을 지우면 대표 사진이 플레이스홀더로 돌아가요.

## 데이터 저장 방식 (로컬 모드와 계정 모드)

| | **로컬 모드 (기본, 데모 공개용)** | **계정 모드 (Supabase)** |
|---|---|---|
| 설정 | `VITE_DATA_BACKEND` 비움 또는 `local` | `VITE_DATA_BACKEND=supabase` |
| 저장 위치 | 이 브라우저(localStorage)에만 | Supabase DB · Storage |
| 로그인 | 닉네임만 정하는 임시 프로필 | 이메일 · 비밀번호 + 이메일 인증 |
| 리뷰 · EXP | 브라우저 안에서 계산 | 서버 트리거가 결정 (하루 EXP 상한) |
| 커뮤니티 · 명예의 전당 | "예시 데이터"로 표시, 글쓰기 없음 | 실제 기록으로 계산, 글쓰기 · 댓글 · 좋아요 |

- 화면에 보이는 **예시 데이터는 모두 "예시"라고 표시**하고, 실제 기록과 섞지 않아요.
- 연결에 실패하면 로컬에 몰래 저장하지 않고 오류를 보여줘요.
- 배포된 데모는 **로컬 모드**예요. 방문자의 기록은 방문자의 브라우저에만 남아요.

## 사용 기술

- **React 19** + **Vite 8**
- **MUI (Material UI) 9**: UI 컴포넌트와 테마 (`src/theme.js`)
- **React Router 7**: 페이지 이동 (`HashRouter`)
- **Lenis**: 부드러운 스크롤
- **카카오 지도 SDK**: 장소 검색 · 월드맵
- **Supabase**: 계정 모드의 인증 · DB (RLS) · Storage · Edge Functions (`supabase/`)

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:5173/my-first-website/my-bakery-review/` 를 열어요 (주소 끝의 경로가 꼭 필요해요).

### 환경 변수

`env.example`을 복사해서 `.env`를 만들어요. `.env`는 git에 올라가지 않아요.

```
VITE_KAKAO_JS_KEY=발급받은_JavaScript_키
VITE_DATA_BACKEND=local
```

- 계정 모드를 쓸 때만 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`를 더해요. 비밀 키(`service_role` 등)는 브라우저 설정에 절대 넣지 않아요.
- 카카오 키는 **JavaScript 키**를 써요 (REST 키는 브라우저에 두면 안 돼요). 카카오 개발자 콘솔의 **플랫폼 → Web**에 사이트 주소(`https://yrkim2605-wq.github.io`, 개발용 `http://localhost:5173`)를 등록해야 지도와 검색이 동작해요.

## 명령어

| 명령어 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm run build` | 배포용 빌드 (저장소 루트의 `my-bakery-review/` 폴더에 만들어져요) |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run lint` | 코드 검사 (ESLint) |
| `node supabase/tests/<이름>.test.mjs` | 개별 검증 (EXP 계산, 저장소, 반응형 넘침, 글자 대비 등) |

DB 정책 · 서버 함수 검증 테스트(`rls`, `reports`, `storage-policy` 등)는 PGlite(브라우저·노드에서 도는 Postgres)로 실행해요. 파일 위쪽 주석의 `PGLITE_DIR` 안내를 따라요.

## 폴더 구조

```
src/
├── api/          # 카카오 장소 검색
├── assets/       # 이미지(WebP) · 일러스트 · 장식
├── components/
│   ├── common/   # 카드, 캐러셀, 제목, 스티커 등 공통 컴포넌트

│   └── home · bakery · mypage · community · ranking/  # 화면별 컴포넌트
├── constants/    # 게임 규칙, 레벨, 배지, 샘플 데이터
├── context/      # 전역 상태 Provider
├── hooks/        # Provider 값을 꺼내 쓰는 hook
├── lib/          # 데이터 모드 스위치, Supabase 클라이언트
├── pages/        # 페이지 컴포넌트
├── storage/      # 로컬 / 계정 저장소 (같은 인터페이스)
├── utils/        # EXP · 레벨 계산 등 도우미 함수
└── theme.js      # MUI 테마 (색상 · 글꼴 · 컴포넌트 스타일)
supabase/
├── migrations/   # DB 스키마 · RLS · 저장소 정책
├── functions/    # Edge Functions (빵집 확인, 계정 탈퇴)
└── tests/        # 검증 스크립트
docs/             # 설계 · 점검 · 배포 문서
```

## 알려진 한계 (공개 베타 전 해결할 항목)

이 사이트는 포트폴리오 데모(로컬 모드)로 공개해요. 실제 사용자 대상 서비스(계정 모드)로 운영하려면 아래가 더 필요해요.

- **사진 승인 시스템 없음**: 계정 모드에서는 승인 전 리뷰 사진이 바로 빵집 대표 사진이 될 수 있어요. 운영자 승인 · 비공개 저장소 설계가 필요해요 (`docs/beta-launch-plan.md`).
- **약관 · 개인정보처리방침은 초안**이에요. 운영자 · 문의처 · 보관 기간은 확정 전이라 화면에 "확인 필요"로 표시돼요.
- 신고 · 운영자 처리, 회원 탈퇴, 이메일 발송 설정은 구현되어 있지만 실서버 전체 시험이 남아 있어요.
- 방문 체크("다녀왔어요")는 실제 방문을 인증하지 않아서 EXP와 도감에는 반영되지 않아요.
- 레벨 혜택(쿠폰 등)은 아직 제공하지 않는 "예정" 항목이에요.

자세한 설계 · 점검 기록은 `docs/` 폴더에 있어요.
