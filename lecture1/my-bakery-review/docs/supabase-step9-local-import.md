# 로컬 기록 → 내 계정 가져오기

> 상태: 구현 + 자동 검증 완료 / **실제 브라우저에서의 확인은 사용자 작업 필요**
> 서버(DB) 변경은 없어요. 새 마이그레이션도 없고, 기존 저장 규칙(서버 검증 · EXP 계산 · 하루 한도 · RLS)을 그대로 거쳐요.

## 1. 한눈에 보기

계정 모드(`VITE_DATA_BACKEND=supabase`)로 로그인하면, 이 브라우저(localStorage)에 예전에 남겨 둔 **모험 일지**와 **다녀왔어요 체크**를 내 계정으로 옮길 수 있어요.

- 위치: **내 모험가(마이페이지)** 맨 위에 “이 브라우저에 있던 기록을 가져올까요?” 카드 (가져올 기록이 남아 있을 때만 보여요)
- 흐름: 카드 → **확인 화면(미리보기, 읽기만 해요)** → **최종 확인** → 하나씩 저장 → 결과
- 로컬 모드에서는 이 카드가 나오지 않아요.

## 2. 요청 사항별 구현

| # | 요청 | 구현 | 검증 |
|---|---|---|---|
| 1 | 이전 전에 대상 / 불가 기록 미리 보여주기 | 확인 화면에 이전 가능 · 수정 필요 · 이전 불가 · 이미 있음을 나눠 보여주고 **이유**를 항목마다 표시 | 화면 문구 테스트 26개 |
| 2 | 최종 확인 전에는 서버에 저장하지 않기 | 확인 화면은 서버를 **읽기만** 해요. 저장 함수는 `confirmed === true`가 아니면 실행을 거부해요 (“가져오기 시작” 버튼에서만 true) | `confirmed` 없이 호출 → 거부, 서버 호출 0번 · 상태 기록 0번 |
| 3 | 성공해도 localStorage 자동 삭제 금지 | 이 브라우저의 일지 · 방문 · 프로필은 **읽기만** 해요(삭제/수정 코드 없음). 읽을 때 깨진 값을 백업하려고 쓰는 일도 하지 않아요 | 실행 전후 원본이 동일, 삭제 호출 0번 |
| 4 | 오류 시 성공/실패 구분 + 중단 지점부터 재시도 | 하나씩 저장하고 **성공할 때마다 바로** 계정별 이전 상태를 남겨요. 한도 · 연결 · 서버 문제는 계속 두드리지 않고 멈춰요. 결과는 성공 / 사진 없이 성공 / 이미 있음 / 실패 / 시도 못 함으로 구분하고, “남은 기록 이어서 가져오기”로 이어가요 | 한도 · 연결 오류에서 멈춤 → 이어서 하기, 사용자 멈춤 |
| 5 | 중복 저장 · EXP 중복 지급 방지 | 서버의 “빵집당 일지 1개” 규칙이 마지막 방어선이에요. 이미 이전한 항목은 목록에서 빠지고, 상태가 사라진 채로 다시 실행해도 서버가 “이미 있음”으로 걸러요 | 재실행 시 중복 저장 0, 이전 상태 기록 |
| 6 | 기존 계정 기록 덮어쓰기 금지 | 이미 계정에 있는 일지 · 체크는 **건너뛰어요**. 실행 도구에는 수정/삭제 함수가 아예 없어요(저장 `create` · `add`만) | 기존 내용 유지 확인 |
| 7 | 날짜가 서버 저장 날짜가 된다는 안내 | 확인 화면 맨 위와 최종 확인 화면에 “작성 날짜는 원래 날짜가 아니라, 가져오는 때의 서버 저장 날짜로 기록돼요” 표시 | 문구 테스트 |
| 8 | 사진 크기 · Storage 정책 확인, 사진 때문에 글 유실 금지 | 서버 정책(`0003_storage.sql`): **JPEG/WebP, 1MB 이하**. 기록마다 점검해서 맞지 않으면 “사진은 제외, 글만 가져와요” 표시. 업로드가 실패해도 **사진 없이 글만** 저장해요 | 큰 사진 · PNG · 업로드 실패 시 글 보존 |
| 9 | 예시 빵집 등 불가 항목 이유 표시 | 예시 빵집 / 빵집 위치 정보 필요 / 너무 짧음 / 이미 있음 / 중복 등 이유를 항목마다 표시 | 문구 테스트 |
| 10 | 계정별 이전 상태 관리 | 이전 상태는 **계정 ID가 들어간 키**(`my-bakery-review:v1:import-state:<계정ID>`)에 저장돼요. 다른 계정 ID가 들어 있는 파일은 무시해요 | 계정 A에서 이전 → B에서는 그대로 보임 |
| 11 | RLS · EXP · 하루 한도 유지 | 서버 변경 없음. 일지는 평소 저장과 같은 경로(빵집 확인 서버 함수 → 일지 저장)를 거쳐요 | 기존 서버 테스트 모두 통과 |

### 20자 미만 일지
이전 전에 **그 자리에서 고쳐 쓸 수 있어요**(입력창 + “조금만 더 자세히 적어주세요! (N자 남음)”). 20자 이상이 되면 이전 대상으로 바뀌고, 고치지 않으면 건너뛰어요(원본은 그대로예요).

## 3. 알아둘 제약

- **작성 날짜**는 서버가 정해서 원래 날짜가 옮겨지지 않아요.
- **EXP**는 서버 규칙 그대로예요: 일지 EXP 하루 100까지 · 하루 일지 20개까지. 많이 가져오면 일부는 EXP 없이 저장되거나 내일로 미뤄져요. 확인 화면에 **예상 결과**(오늘 저장 N개, EXP 대상 N개, 예상 EXP)를 미리 보여줘요. (도감 · 일지 수는 EXP와 상관없이 전부 남아요)
- **빵집 위치 정보**: 서버에 아직 없는 빵집은 위치 정보가 있어야 서버 함수가 등록할 수 있어요. 지금 지도 목록에서 위치를 못 찾으면 “이전 불가 · 빵집 정보 필요”로 표시하고, 지도에서 해당 지역을 한 번 연 뒤 다시 시도하면 돼요.
- **새 빵집 확인**은 10분에 20곳까지예요(서버 함수 제한). 넘으면 멈추고 “몇 분 뒤에 이어서”라고 알려줘요.
- 같은 빵집의 일지가 여러 개(여러 임시 프로필)면 계정에는 빵집당 1개만 저장돼서 먼저 나온 것만 이전돼요.

## 4. 실제 브라우저에서 확인하기

> ⚠️ 가져오기는 **실제 서버에 저장**해요. 테스트로 가져온 일지는 내 계정에 진짜 남아요(앱에서 직접 삭제할 수 있어요).

### 준비: 가져올 기록이 있어야 카드가 보여요
- 예전 로컬 모드에서 쓴 기록이 이 브라우저에 남아 있다면 바로 카드가 나와요.
- 없다면 시험용으로 만들 수 있어요(이 브라우저에만 만들고 서버에는 아무것도 저장하지 않아요).
  1. 지도에서 **서로 다른 실제 빵집 2곳**의 상세 화면을 열어 주소의 빵집 ID를 확인해요 (예: `#/bakery/12345678` → `12345678`). 이미 일지를 쓴 빵집은 피하세요(“이미 계정에 있음”으로 나와요).
  2. F12 → Console에 아래를 붙여넣고 `BAKERY_ID_1` · `BAKERY_ID_2`를 바꿔 실행해요.
  ```js
  localStorage.setItem('my-bakery-review:v1:reviews', JSON.stringify({ version: 1, reviews: [
    { id: 't1', userId: 'local-t', authorNickname: '시험', bakeryId: 'BAKERY_ID_1', bakerySource: 'kakao', bakeryName: '시험 빵집', districtId: 'seomyeon', rating: 4.5, content: '맛있어요 소금빵이 정말 훌륭해서 또 가고 싶어요 강력 추천합니다', photo: null, createdAt: '2026-01-01T00:00:00.000Z', updatedAt: '2026-01-01T00:00:00.000Z' },
    { id: 't2', userId: 'local-t', authorNickname: '시험', bakeryId: '5', bakerySource: 'sample', bakeryName: '예시 빵집', districtId: 'seomyeon', rating: 4, content: '예시 빵집 일지라서 이전할 수 없어요 테스트용 내용입니다', photo: null, createdAt: '2026-01-01T00:00:00.000Z', updatedAt: '2026-01-01T00:00:00.000Z' },
    { id: 't3', userId: 'local-t', authorNickname: '시험', bakeryId: 'BAKERY_ID_2', bakerySource: 'kakao', bakeryName: '짧은 일지 시험', districtId: 'seomyeon', rating: 3, content: '짧아요', photo: null, createdAt: '2026-01-01T00:00:00.000Z', updatedAt: '2026-01-01T00:00:00.000Z' }
  ] }))
  ```
  3. 새로고침해요. 기대: 카드에 “모험 일지 3개”, 확인 화면에서 t1은 **이전 가능**, t2는 **이전 불가 · 예시 빵집**, t3은 **수정 필요**(고쳐 쓰는 입력창)로 보여요. (되돌리려면 같은 키를 `localStorage.removeItem('my-bakery-review:v1:reviews')`로 지우면 돼요 — 앱은 지우지 않아요)

### 확인 순서
1. 계정 모드로 로그인 → **내 모험가** 맨 위의 카드와 남은 개수가 맞는지
2. **가져올 기록 확인하기** → 확인 화면에서 서버에 아무것도 저장되지 않았는지 (Table Editor의 reviews 행 수가 그대로)
3. 안내 3개(날짜 · 원본 보존 · EXP 규칙), 항목별 상태와 이유, 예상 결과 문구
4. 20자 미만 일지를 고쳐 쓰면 입력창이 유지되고 상태가 “이전할 수 있어요!”로 바뀌는지
5. 선택을 해제해 보고 **선택한 N개 가져오기 → 최종 확인 → 가져오기 시작**
6. 진행 표시 → 결과 화면(성공 / 건너뜀 / 실패 구분). 내 모험가의 EXP · 일지가 바로 반영되는지
7. 새로고침 후 **이전한 기록이 카드/목록에서 빠지는지**, 이 브라우저의 원본(위의 시험용 키)은 그대로인지
8. 다른 계정으로 로그인하면 카드가 다시 보이는지(이전 완료 표시는 계정별)
9. 모바일 폭(창을 좁히기)에서 대화창이 전체 화면으로 열리고 글자가 잘리지 않는지
