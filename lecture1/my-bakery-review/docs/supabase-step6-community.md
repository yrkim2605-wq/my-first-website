# Supabase 6단계 · 커뮤니티(글 · 댓글 · 좋아요) 연동

> 상태: 구현 + 자동 검증 완료 / **0004 적용과 진짜 서버에서의 화면 확인은 사용자 작업 필요**
> 기본값은 여전히 `VITE_DATA_BACKEND=local`(예시 글). 기존 리뷰 · 방문 체크 · EXP · 레벨 · 도감 데이터는 건드리지 않아요.

## 1. 무엇이 바뀌었나요?

| 구분 | 계정 모드 (`VITE_DATA_BACKEND=supabase`) | 로컬 모드 (기본) |
|---|---|---|
| 글 목록 · 상세 | 서버에 저장된 **실제 글만** 표시 (다른 사용자 글도 보여요) | 예시 글 + **‘예시’ 표시** 유지 |
| 글쓰기 · 수정 · 삭제 | 로그인 + 이메일 인증을 마친 사용자, **내 글만** 수정 · 삭제 | 없음 (안내 문구만) |
| 댓글 · 답글 | 쓰기 · 삭제만 (**수정 없음**, 답글은 1단계까지) | 화면에서만 보이고 저장 안 됨 (안내 유지) |
| 좋아요 | 계정당 글 1개에 1번, 서버가 센 숫자 | 화면에서만 |
| 댓글 싫어요 · 댓글 수정 | **숨김** | 예시 화면에 그대로 |
| 사진 첨부 | 아직 없음 (다음 단계) | — |
| EXP | **반영 안 됨** (글 · 댓글 · 좋아요는 EXP · 레벨 · 배지와 무관) | — |

작성자 닉네임과 레벨(캐릭터 메달)은 서버가 계산한 값으로 표시돼요.

## 2. 하루 작성 제한 (서버가 지켜요)

한국 시간 기준 하루에 **글 10개 · 댓글 50개 · 좋아요 200개**까지예요. 넘으면 “오늘은 너무 많이 남겼어요…” 안내가 나와요.
(리뷰의 하루 EXP 상한 100과는 별개이고, 커뮤니티 활동은 EXP에 영향을 주지 않아요.)

## 3. 0004 마이그레이션 적용 방법 (초보자용)

> 0004는 **댓글 목록용 ‘뷰’(보기 전용 표) 하나만 추가**해요. 기존 표와 데이터는 건드리지 않고, 여러 번 실행해도 안전해요.
> 글 · 댓글 · 좋아요 표와 보안 규칙은 이미 1단계(0001 · 0002)에서 만들어져 있어요.
> ⚠️ **0004를 적용하기 전에는 계정 모드의 글 상세에서 댓글을 불러오지 못해요.** (“글을 불러오지 못했어요”)

1. [Supabase 대시보드](https://supabase.com/dashboard)에 로그인해서 이 프로젝트를 열어요.
2. 왼쪽 메뉴에서 **SQL Editor**(`</>` 모양)를 눌러요.
3. **New query**(새 쿼리)를 눌러 빈 입력창을 열어요.
4. 내 컴퓨터의 `lecture1/my-bakery-review/supabase/migrations/0004_community.sql` 파일을 메모장(또는 VS Code)으로 열고 **전체 선택(Ctrl+A) → 복사(Ctrl+C)** 해요.
5. SQL Editor 입력창에 **붙여넣기(Ctrl+V)** 해요.
6. 오른쪽 아래 초록색 **Run**(실행) 버튼을 눌러요. (단축키 Ctrl+Enter)
7. 아래 결과 칸에 **`Success. No rows returned`**가 나오면 성공이에요.
   - 빨간 오류가 나오면 **글자를 그대로 복사해서 알려 주세요.** (0001 · 0002가 아직 적용되지 않았다면 `relation "public.user_progress" does not exist` 같은 오류가 나요.)
8. (확인) 왼쪽 **Table Editor** 맨 아래쪽, 또는 SQL Editor에 아래를 실행해서 오류 없이 결과(0줄도 정상)가 나오면 끝이에요.
   ```sql
   select * from public.comment_feed limit 5;
   ```

되돌리고 싶다면(보통 필요 없어요): `drop view public.comment_feed;` — 기존 데이터에는 영향이 없어요.

## 4. 진짜 서버에서 직접 확인하는 방법

준비: 계정 2개(A, B)가 있으면 가장 좋아요. 둘 다 이메일 인증을 마친 계정이어야 해요. 한 개만 있어도 1~7번은 확인돼요.

1. `.env`가 `VITE_DATA_BACKEND=supabase`인 상태로 `npm run dev` → `http://localhost:5173/my-first-website/my-bakery-review/#/community`
2. 로그인 전: 글 목록이 보이고(처음엔 비어 있어요), 버튼이 **‘로그인하고 글쓰기’**인지
3. A로 로그인 → **새 글 쓰기** → 카테고리 · 제목 · 내용 입력 → **글 올리기** → 상세 화면으로 이동하는지
4. 목록에 내 글이 보이는지, 대시보드 Table Editor → **`posts`**에 행이 생겼는지
5. 상세에서 **좋아요**(숫자 +1, 다시 누르면 취소), **댓글**, **답글**이 되는지, **글 수정**이 되고 “수정됨”이 표시되는지
6. 댓글에는 **수정 · 싫어요가 없는지**
7. 새로고침해도 모두 유지되는지, 로그아웃하면 글은 보이지만 쓰기 · 좋아요는 로그인 안내가 나오는지
8. B로 로그인 → A의 글이 보이고, B는 A의 글에 **수정/삭제 버튼이 없는지**, 주소창에 `#/community/글ID/edit`을 직접 넣어도 “내가 쓴 글만 고칠 수 있어요”가 나오는지
9. 마이페이지의 **EXP · 레벨 · 도감 숫자가 글을 쓰기 전과 같은지**

문제가 생기면 화면의 안내 문구(키 제외)를 알려 주세요.

## 5. 자동 검증

| 시험 | 방법 | 결과 |
|---|---|---|
| 서버 규칙 · 보안 (진짜 Postgres/PGlite) | `PGLITE_DIR=<pglite 설치 폴더> node supabase/tests/rls.test.mjs` | 102개 통과 (기존 75 + 커뮤니티 27) |
| 커뮤니티 저장소 (가짜 클라이언트) | `node supabase/tests/community-repository.test.mjs` | 43개 통과 |
| 화면 시험용 가짜 서버 | `npx vite --config supabase/tests/ui-fake/vite.fake.config.js --port 5195` → 콘솔에서 `__fake.seedPost()`, `__fake.seedComment(글ID)`, `__fake.setSignedIn(false)` | 코드 작성 완료 |

커뮤니티 보안 시험이 확인하는 것: 비로그인 · 이메일 미인증의 글/댓글/좋아요 차단, 남의 글 수정 · 삭제 0행, 작성자 · 작성일 변경 불가, 남의 이름으로 좋아요 불가, 댓글 수정 불가, 답글의 답글 거부, 글/댓글 길이 제한, 남의 폴더 사진 경로 거부, 하루 상한(글 10 · 댓글 50 · 좋아요 200), 글 삭제 시 댓글 연쇄 삭제, 커뮤니티 활동이 EXP · 레벨 · 리뷰 기록에 영향 없음.

## 6. 알아둘 점

- 하루 상한은 “오늘 쓴 글 수”를 세므로, 글을 지우면 그만큼 다시 쓸 수 있어요(리뷰와 같은 방식).
- 글 목록은 최근 100개까지 보여요. 더 많아지면 ‘더 보기’가 필요해요(다음 단계 후보).
- 로컬 기록 → 계정 이전 절차는 아직 없어요 (7~8단계 이후).
