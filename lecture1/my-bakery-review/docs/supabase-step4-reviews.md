# Supabase 4단계 · 프로필 · 리뷰 · EXP · 레벨 · 배지 연동

> 상태: 구현 + 자동 검증 완료 / **빵집 확인 서버 함수(register-bakery) 배포와 실제 서버 시험은 사용자 작업 필요**
> 기본값은 여전히 `VITE_DATA_BACKEND=local`. 계정 모드(`supabase`)에서만 아래 기능이 서버를 써요.

## 1. 계정 모드에서 달라진 점

| 기능 | 계정 모드 동작 |
|---|---|
| 프로필 | 가입한 닉네임(`profiles`)을 상태창 · 리뷰 · 랭킹에 표시 |
| 리뷰 작성 · 수정 · 삭제 | **Supabase에 저장**, 내 리뷰만 수정·삭제, 다른 모험가에게 공개. 연결 실패 시 **저장되지 않았다고 알리고 로컬에 저장하지 않음** |
| EXP | **서버(DB 트리거)가 지급 여부를 결정**. 앱은 EXP 값을 보내지 않고, 서버가 정한 `exp_review / exp_photo`를 읽어 표시 |
| 레벨 | 내 EXP로 계산(서버 SQL과 같은 규칙 · 동일성 자동 검증), 리뷰 카드의 **작성자 레벨은 서버 뷰 값** |
| 퀘스트 · 배지 · 도감 | EXP 받은 리뷰 기준 퀘스트, 쓴 리뷰 기준 도감, **현재 리뷰로 재계산하는 배지**(리뷰를 지우면 회수) |
| 하루 EXP 상한 | 서버 `game_settings.daily_exp_cap`(기본 100). 저장 전에 "오늘 한도를 채워서 EXP 없이 저장돼요" 안내 |
| 예시 빵집 | DB에 없어서 저장 불가("실제 빵집을 골라 주세요") |
| 사진 | 브라우저에서 줄인 JPEG을 `photos/{내 ID}/…`에 업로드, 일지에는 경로만 저장. 저장 실패 시 올린 사진 정리 |
| 아직 연결 전 | 방문 체크(5단계), 커뮤니티(6단계), 실제 랭킹(7단계), **기존 로컬 기록 이전(별도 절차)** |

로컬 모드는 이전과 똑같아요(로컬 리뷰는 "EXP 여부 칸이 없으면 모두 EXP 대상"으로 계산해서 결과가 그대로예요).

## 2. EXP 규칙 (정책 3번)

| 요구 | 구현 |
|---|---|
| 리뷰 작성 시 EXP | 서버 트리거가 결정 (리뷰 30, 작성 때 사진이 있으면 +10, 퀘스트 1회성 보너스) |
| 수정만으로 추가 EXP 없음 | `exp_*`는 수정 불가. 고쳐 쓰기 창에도 "EXP가 늘지도 줄지도 않아요" 안내 |
| 삭제 시 회수, 레벨 하락 가능 | EXP를 리뷰에서 계산하므로 삭제하면 사라짐 → 레벨도 내려감(화면에서 확인) |
| 중복 지급 방지 | 사용자·빵집당 리뷰 1개(`unique`) → 같은 빵집 EXP는 평생 1회, 요청 재전송도 거부 |
| 클라이언트가 조작 불가 | EXP 칸에 쓰기 권한 없음 + 트리거가 덮어씀 + 저장소가 EXP 값을 보내지 않음 |
| 유효한 빵집만 | 외래키(`bakeries`) + 서버 함수가 카카오로 실제 존재를 확인한 뒤에만 등록 |
| 하루 상한 | 리뷰·사진 EXP 합계 하루 100 (한국 시간), 하루 작성 20개. 숫자는 `game_settings`에서 변경 |

## 3. 빵집 확인 서버 함수 `register-bakery` (사용자가 배포)

리뷰에 EXP를 주려면 빵집이 DB(`bakeries`)에 있어야 해요. 처음 리뷰가 쓰이는 빵집은 앱이 이 함수를 불러서 등록해요.
함수가 하는 일: 로그인(+이메일 인증) 확인 → **카카오 로컬 API로 같은 ID의 제과·베이커리가 실제로 있는지 확인** → 이름·주소·좌표·**지역은 카카오 좌표 기준으로 서버가 정해서** 저장 (클라이언트가 보낸 값은 쓰지 않음).

### 배포 순서 (Supabase 대시보드)
1. **카카오 REST API 키 준비**: [카카오 개발자 콘솔](https://developers.kakao.com/console/app) → 내 애플리케이션 → 앱 키 → **REST API 키** (지도에 쓰는 JavaScript 키와 다른 키예요).
   - 호출이 거절되면(401/403) 앱 설정에서 카카오맵(로컬) 사용 설정이 켜져 있는지 확인해 주세요.
2. **비밀값 등록**: 대시보드 **Edge Functions → Secrets → Add new secret**: 이름 `KAKAO_REST_API_KEY`, 값에 REST API 키. (프런트 · `.env` · 대화에는 넣지 않아요.)
3. **함수 만들기**: **Edge Functions → Deploy a new function → Via Editor**, 이름 **`register-bakery`**(정확히), 편집기 내용을 지우고 `supabase/functions/register-bakery/index.ts` **전체를 붙여넣기** → Deploy.
   - 클립보드로 복사: `Get-Content supabase\functions\register-bakery\index.ts -Raw | Set-Clipboard`
4. 함수 설정에서 **Verify JWT는 끄는 것을 권장**: 이 함수가 토큰을 직접 확인해서(로그인 + 이메일 인증) 중복이고, 새 API 키 방식과 플랫폼 기본 검증이 충돌하는 경우가 있어요. 켜 둔 채 401이 나면 꺼 보세요.
5. 배포 후 로그(Edge Functions → register-bakery → Logs)에서 오류를 볼 수 있어요.

> 함수가 없으면 앱이 "빵집 확인 기능이 아직 설정되지 않았어요 (일지는 저장되지 않았어요)"라고 알려줘요. 조용히 실패하지 않아요.

## 4. 실제 서버에서 직접 확인하는 방법

> 이 단계의 자동 검증은 가짜 서버로 했어요. 아래는 **진짜 Supabase로 처음 도는 부분**이니 꼭 확인해 주세요.

1. `.env`를 `VITE_DATA_BACKEND=supabase`로 바꾸고 `npm run dev` 재시작, 이메일 인증한 계정으로 로그인
   (카카오 지도가 보이려면 카카오에 등록된 주소여야 해요: `localhost:5173` — 포트폴리오 서버를 끄고 5173에서 실행)
2. 지도에서 **실제 빵집**을 골라 상세 → **모험 일지 쓰기** → "저장하면 EXP +50" 확인 → 저장
3. 기대 결과
   - 보상 창에 +30 (첫 일지면 +20 퀘스트)
   - 대시보드 Table Editor → **`bakeries`**에 그 빵집, **`reviews`**에 일지(`exp_review = true`)
   - 마이페이지에 EXP · 퀘스트 · 도감 1곳
   - 다른 브라우저/기기에서 로그인해도 같은 일지·EXP
4. **삭제** → EXP 회수, 레벨이 내려가는지(필요 시)
5. 사진을 붙여 저장 → Storage `photos/{내 ID}/` 파일 생성 확인, 일지 카드에 사진 표시
6. 하루 EXP 100을 넘기면 안내 문구가 나오고 EXP 없이 저장되는지
7. **`VITE_DATA_BACKEND=local`로 되돌리면** 이 브라우저의 기존 로컬 기록이 그대로 보여요

문제가 생기면 화면의 안내 문구(비밀 값 제외)와, 가능하면 Edge Function 로그의 오류를 알려 주세요.

## 6. 알려진 한계

- **진짜 서버 왕복 · 함수 · Storage 정책은 아직 실제로 확인하지 못했어요**(위 4번).
- **지역 기준 차이**: 앱 지도는 검색어("해운대 빵집" 등)로 지역을 나누고, 서버는 카카오 좌표에서 **가장 가까운 지역 중심**으로 정해요. 경계의 빵집은 화면의 지역 칩과 서버의 퀘스트 계산이 다를 수 있어요.
- 방문을 인증하지 않아요. "실제로 존재하는 빵집"만 확인해요(EXP 어뷰징을 완전히 막지는 못해요).
- 목록은 **최신 500개 + 내 일지 전체**만 불러와요(그 이상은 페이지 처리 필요, 이후 개선). 새로고침하기 전에는 다른 사람의 새 일지가 보이지 않아요(실시간 구독 없음).
- 앞서 말씀드린 **기존 로컬 기록의 계정 이전**은 이 단계에 포함하지 않았어요(로컬은 그대로 보존).
- 헤더 위 "지금 가입하고…" 배너는 로그인 상태와 상관없이 보이는 기존 동작이에요.
