## 2. 백업 보관처 비교: GitHub(비공개 저장소) vs 서울 리전 별도 Supabase 프로젝트

> 실제 저장소 · 프로젝트는 만들지 않았어요. 아래는 공식 문서와 현재 설계 기준 비교예요.

### 먼저, 두 선택 모두에 해당하는 사실
- **백업 작업은 어느 쪽이든 GitHub Actions에서 돌아가요.** DB를 내보내는 순간 암호화 전의 덤프가 GitHub 작업 서버(임시 서버)에 잠깐 존재해요. 그래서 **어느 쪽을 골라도 GitHub는 개인정보 고지 대상이에요.** "서울 Supabase에 저장하면 국외 이전 고지가 필요 없다"는 결론은 성립하지 않아요.
- 저장소만 서울로 옮기고 싶다면 Actions 대신 **내 PC에서 백업 작업을 돌리는** 방식이어야 하는데(아래 C안), PC가 꺼져 있으면 백업이 빠져요.

### 비교표

| 기준 | A. GitHub 비공개 저장소 (Artifact) | B. 서울 리전 별도 Supabase 프로젝트 (Storage에 암호화 파일) | C. 내 PC에서 실행 + 외장/로컬 보관 |
|---|---|---|---|
| **보안: 접근 경로** | 저장소 접근 권한(소유자 1명) + Actions 비밀값. 파일은 암호화(키 2개) | 프로젝트 비공개 버킷 + **서비스 키(권한 큼)를 GitHub 비밀값에 추가로 저장**. 파일은 암호화 | 작업 스케줄러 · PC 보안에 의존. 키 개인키는 PC에 두지 않아요(공개키만 필요) |
| **보안: 장애 · 계정 위험 분산** | 주 DB(Supabase)와 **다른 회사** → Supabase 계정 · 프로젝트 문제와 분리됨 | 주 DB와 **같은 회사 · 같은 계정(조직)** → 계정 정지 · 과금 · 탈취 시 같이 위험 | 회사 무관, PC 분실 · 고장 위험 |
| **개인정보 고지** | GitHub 항목 필요. **저장 국가를 GitHub가 공개하지 않음 → 국가 기재가 어려움** | 저장소 자체는 서울로 적을 수 있음(저장 지역 확인 필요). 그래도 **Actions 때문에 GitHub 항목은 여전히 필요** | GitHub 불필요(Actions 미사용). 국외 이전 없음 |
| **비용 (무료 한도 안)** | $0. Artifact 저장 500MB(Packages와 공유), Actions 월 2,000분 | Free는 **프로젝트 2개까지(조직 전체 합산)**. 이미 다른 사이트용 프로젝트가 있으면 **3번째를 못 만들 수 있어요**(대시보드 확인 필요, 정지된 프로젝트는 불포함). 초과 시 유료 플랜 필요. 저장 1GB, 파일 50MB, **1주 비활동 시 정지**(업로드가 활동으로 치는지 미확인) | $0 (전기 · 디스크) |
| **복구 난이도** | `gh run download` → `age -d` → `pg_restore`. 단순 | Storage에서 다운로드(API 또는 대시보드) → `age -d` → `pg_restore`. 단순 | 파일 복사 → `age -d` → `pg_restore`. 가장 단순하지만 PC가 살아 있어야 함 |
| **자동 삭제(보관 기간) 관리** | cleanup 워크플로 + 자동 만료(이중 장치) | 자동 만료 기능이 없어 **삭제 작업(API)만** 의존 → 장치가 1개로 줄어요 | 스케줄러로 직접 삭제(PC 의존) |
| **자동화 안정성** | 높음 (GitHub 서버가 항상 켜져 있음) | 높음 (단, 프로젝트 정지 위험) | 낮음 (PC 전원 · 절전 · 로그인 상태) |
| **키 · 비밀값 수** | 3개 (DB 주소, 공개키 2) | 4개 이상 (+ 백업 프로젝트 서비스 키) | DB 주소는 PC에 저장 필요 |

### 추천: **A안 (GitHub)을 유지**하고, 법률 검토에서 문제가 되면 C안으로 전환
- B안은 이름과 달리 국외 이전 고지를 줄여주지 못하고(GitHub Actions는 그대로), 주 DB와 같은 회사 · 계정에 백업이 같이 있어서 **장애 분산이 오히려 나빠지고**, 삭제 안전장치도 1개로 줄고, 무료 프로젝트 수 제한에 걸릴 수 있어요.
- A안은 단순하고 안전장치가 많지만 **저장 국가를 확정해서 쓸 수 없다**는 약점이 있어요. 이 약점이 법률 검토에서 "국가 기재 필수"로 판단되면 A안은 부적합하고, 그때는 B가 아니라 **C안(PC 실행)** 으로 가야 GitHub를 데이터 경로에서 뺄 수 있어요 (대신 PC 의존).
- 따라서 순서: ① 법률 검토에서 GitHub 고지 방식(국가 미공개 시 기재 방법) 확인 → ② 가능하면 A 확정 → ③ 불가하면 C 검토.
- 확인하지 못한 것: Supabase Free의 정확한 프로젝트 수 제한이 이 계정에 어떻게 적용되는지, 업로드가 비활동 정지를 막는지, GitHub Artifact의 저장 국가.

## 4. 방침 ↔ 약관 ↔ 실제 운영 일치 점검

| 항목 | 방침 | 약관 | 실제 운영 (초안 기준) |
|---|---|---|---|
| DB 백업 주기 | 매일 만든다 (B') | 하루에 한 번 자동으로 백업하도록 운영 (G) | 매일 03:00 KST (`backup-db`) |
| 사진 백업 | 별도로 백업하지 않는다 (C', D') | 현재 별도 백업 대상 아님 (G) | 미구현 |
| 보관 · 삭제 | 21일 초과 시 삭제 시도, 25일 자동 만료 (B') | 보관 기간(자동 만료 25일 설정) (H) | cleanup 21일 + `retention-days: 25` |
| 물리적 삭제 시점 | 저장 서비스 정책에 따름 (C') | (언급 없음, 방침 참조) | GitHub 내부 처리 — 보장 안 함 |
| 탈퇴 후 백업 잔존 | 삭제한 정보가 백업에 남을 수 있음 (B') | 보관 기간 동안 남을 수 있음 (H) | 위와 같음 |
| 사진 삭제 | 탈퇴 처리 중 먼저 삭제 요청, 실패하면 탈퇴 미완료, 캐시 · 사본 유의 (A') | 탈퇴 시 삭제 (기존) | `delete-account` 함수 |
| 암호화 · 보관처 | 암호화, 키는 운영자만, GitHub 작업 서버 · 비공개 저장소 (C', D') | (약관에는 없음 — 방침 참조) | age 키 2개, Actions |
