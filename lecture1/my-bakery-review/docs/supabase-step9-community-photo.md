# 커뮤니티: 글 목록 “더 보기” · 사진 첨부 · 터치 영역

> 상태: 구현 + 자동 검증 완료 / **0008 적용과 실제 브라우저에서의 확인은 사용자 작업 필요**
> 기존 리뷰 · EXP · 랭킹 · 방문 기록 · DB 보안 정책(RLS)은 바꾸지 않았어요. 서버 변경은 `0008` 하나(사진 저장소 “내 폴더 읽기” 정책)뿐이에요.

## 1. 글 목록 “더 보기” (20개씩)

- 첫 화면은 20개 + **“더 보기 (20개씩)”** 버튼. 누르면 지금 보이는 글 수만큼 건너뛰고 다음 20개를 이어 붙여요. 마지막이면 “마지막 글이에요”.
- **카테고리 · 정렬을 바꾸면 처음부터** 다시 불러와요 (기다리는 동안 조건을 바꾸면 이전 조건의 결과는 버려요).
- **겹침 · 누락 방지**: 정렬을 “기준(최신/좋아요/댓글) → 최신순 → 글 ID순”까지 정해서, 좋아요 수나 작성 시각이 같은 글이 많아도 쪽 경계에서 어긋나지 않아요. 한 건 더 받아서 “다음 쪽이 있는지” 알아내고, 글 ID로 중복도 한 번 더 걸러요. 전체 글 수(`total`)도 보여줘요.
- 실패하면 이미 보이는 글은 그대로 두고 아래에 이유 + “다시 시도”가 나와요.
- 알아둘 점: 쪽을 넘기는 *사이에* 다른 사람이 글을 쓰거나 지우면 쪽 경계가 한 칸 밀릴 수 있어요. 같은 글이 두 번 나오는 일은 막지만(글 ID로 걸러요), 지워진 글 때문에 경계의 글 1개가 건너뛰어질 수는 있어요. 새로고침하면 바로잡혀요.

## 2. 글 사진 첨부 (글 1개에 1장)

| 항목 | 동작 |
|---|---|
| 형식 · 크기 | 고른 사진을 **JPEG 800px**로 줄여요. 1MB를 넘으면 품질을 낮춰(0.8→0.6→0.5, 640px까지) 다시 줄이고, 그래도 안 되면 이유를 알려요. 서버 저장소(photos)는 JPEG/WebP 1MB 이하만 받아요 |
| 글쓰기 | [사진 붙이기] → 미리보기 → [사진 바꾸기] / [사진 빼기] |
| 고치기 | 사진 **교체 · 빼기 · 그대로**. 새로 골랐다가 빼면 기존 사진으로 돌아가요 |
| 보이는 곳 | 글 상세(아치 틀)와 목록 썸네일. **사진이 없는 글은 기존 이모지 디자인 그대로**예요. 사진을 못 불러오면(파일이 지워진 경우 등) 이모지로 돌아가요 |
| 업로드 실패 | 글은 **저장하지 않고**, 제목 · 본문 · 카테고리 · 고른 사진은 그대로 남아요. [다시 시도] / [사진 없이 글만 저장] (고치기에서는 [사진은 그대로 두고 글만 고치기]) 중에서 골라요 |
| 글 저장 실패 | 방금 올린 사진 파일은 지워요 |
| 사진 교체 | 새 사진 올리기 → 글 고치기 → 옛 사진 지우기 (고치기가 실패하면 새 사진만 지우고 옛 사진은 그대로) |
| 글 삭제 | 글을 지운 뒤 사진 파일도 지워요 |
| 정리 실패 | 글 삭제/고치기는 **성공으로 두고**, 화면에 “사진 파일 N개를 서버에서 지우지 못했어요 + 남은 파일 경로”를 알려줘요. 경로는 이 브라우저에 기록돼 있고(계정별) 커뮤니티 화면에서 **[다시 정리하기]**로 다시 지워 볼 수 있어요 |

### 남은 파일을 직접 확인하는 방법
Supabase 대시보드 → **Storage → photos → (내 사용자 ID 폴더)**에서 화면에 나온 파일 이름을 찾아 지울 수 있어요.

## 3. 보안 — 누가 무엇을 할 수 있나

| 동작 | 작성자(본인) | 다른 로그인 사용자 | 비로그인 / 이메일 미인증 |
|---|---|---|---|
| 사진 **보기** | ✅ | ✅ (공개 버킷의 공개 주소) | ✅ |
| 사진 **올리기** (내 폴더 `{내 user_id}/…`) | ✅ | ❌ (남의 폴더 · 폴더 없는 경로 · 다른 버킷 거부) | ❌ |
| 사진 **교체**(이동 포함) · **삭제** | ✅ 내 폴더만 | ❌ (0건) | ❌ |
| 글의 사진 경로 바꾸기 · 빼기 | ✅ 내 글, 내 폴더 경로만 | ❌ (0행) | ❌ |
| 저장소 파일 **목록** 보기 | 내 폴더만 | 남의 폴더 ❌ | ❌ |
| 버킷 설정(1MB · JPEG/WebP · 공개) 바꾸기 | ❌ | ❌ | ❌ |

### 이번에 발견한 문제 → `0008`
0003에는 **읽기(SELECT) 정책이 없었어요.** PostgreSQL은 DELETE/UPDATE가 조건으로 행을 찾을 때 읽기 정책도 요구해서, 작성자 본인도 자기 사진을 지우거나 옮기려 하면 **오류 없이 0건**만 처리돼요 (진짜 Postgres 시험으로 재현). 즉 지금까지 리뷰/글의 사진 파일 정리가 조용히 실패하고 파일이 남았을 수 있어요.
→ `0008_storage_select_own.sql`: 로그인한 사용자가 **내 폴더 파일만** 읽을 수 있는 정책 추가. 남의 폴더는 여전히 못 보고, 사진 보기는 공개 주소라서 그대로이며, 올리기/고치기/지우기 정책(0003)과 비로그인 권한은 그대로예요. 또 앱은 이제 “지웠다고 서버가 확인해 주지 않은” 경우도 실패로 보고 기록해요.

## 4. 0008 적용 방법 (초보자용)

> 사진을 **지우는** 기능(글 삭제 · 사진 교체/빼기)이 실제로 파일을 지우려면 필요해요. 적용하지 않아도 사진 올리기/보기/글 저장은 되지만, 파일 정리는 “지우지 못했어요” 안내가 나와요. 여러 번 실행해도 안전해요.

1. Supabase 대시보드 → **SQL Editor** → **New query**
2. `lecture1/my-bakery-review/supabase/migrations/0008_storage_select_own.sql` 전체를 복사해서 붙여넣기
3. **Run** → `Success. No rows returned`
4. (확인) 새 쿼리:
   ```sql
   select policyname, cmd from pg_policies where schemaname = 'storage' and tablename = 'objects' order by policyname;
   ```
   `photos_delete_own`, `photos_insert_own`, **`photos_select_own`**, `photos_update_own` 네 줄이 보이면 성공이에요.

## 5. 모바일 터치 영역 (최소 44px)

- 수정 · 삭제 · 답글 달기 · 좋아요/싫어요 · 리뷰 카드의 수정/삭제 · 내 일지 목록 버튼/링크 · 사진 빼기 · 맨 위 가입 배너를 **44px 이상**으로 올렸어요. 새 사진 버튼 · 업로드 실패 선택 버튼은 44px, 더 보기 버튼은 48px예요.
- 테마: **터치 기기(`pointer: coarse`)**에서는 작은 버튼을 포함한 모든 MUI 버튼과 나무 간판 작은 버튼이 44px 이상이에요. 마우스 기기의 모양은 그대로예요.
- 앞으로 44px 미만 높이가 소스에 생기면 `touch-targets.test.mjs`가 실패해요.

## 6. 실제 브라우저에서 확인하기

> 먼저 `0008`을 적용해 주세요. 사진 테스트는 실제 서버에 파일을 올려요 (글을 지우면 같이 정리돼요).

**더 보기**
1. 커뮤니티에 글이 21개 이상일 때: 첫 화면 20개 → “더 보기 (20개씩)” → 21번째 이후가 이어지고, 같은 글이 겹치지 않는지, 끝에서 “마지막 글이에요”가 나오는지 (글이 적다면 글을 더 써서 확인)
2. 더 보기를 누른 뒤 **카테고리 탭 / 정렬(최신·좋아요·댓글)**을 바꾸면 맨 위부터 다시 20개가 나오는지
3. 모바일 폭에서 “더 보기” 버튼이 가로 가득 보이고 누르기 편한지

**사진**
4. 글쓰기 → 사진 붙이기 → 미리보기가 나오는지, 글 올리기 → 상세에 사진이 아치 틀로 보이고 목록에도 썸네일로 보이는지 (사진 없는 글은 이모지 그대로)
5. 다른 계정(또는 로그아웃 상태)에서 그 글의 사진이 보이는지, 다른 계정에는 수정/삭제 버튼이 없는지
6. 글 고치기 → 사진 바꾸기 / 빼기 → 저장 후 상세에 반영되는지
7. 큰 사진(수 MB)을 골라도 자동으로 줄어서 올라가는지, PDF 같은 사진이 아닌 파일은 거절되는지
8. (가능하면) 네트워크를 끊거나 개발자 도구에서 오프라인으로 두고 사진 글을 저장 → **작성한 글이 사라지지 않고** [다시 시도] / [사진 없이 글만 저장]이 나오는지
9. 사진 글 삭제 → 목록으로 돌아가고, Storage → photos에서 파일이 사라졌는지. 안 사라졌다면 화면의 “사진 파일을 지우지 못했어요 + 경로” 안내가 나오는지(0008 미적용 시 이렇게 보여요)
10. 모바일 폭에서 수정/삭제/답글 달기/사진 버튼이 손가락으로 누르기 편한지
