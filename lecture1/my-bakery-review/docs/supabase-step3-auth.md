# Supabase 3단계 · 이메일 회원가입 · 로그인

> 상태: 구현 + 자동 검증 완료 / **실제 이메일 가입 흐름은 사용자 확인 필요**(계정을 대신 만들 수 없어서)
> 기본값은 여전히 `VITE_DATA_BACKEND=local` — 켜기 전까지 앱은 이전과 똑같이 동작해요.

## 1. 동작 방식

| 모드 | `.env` | 로그인 | 리뷰·EXP·방문 체크·커뮤니티 |
|---|---|---|---|
| **로컬(기본)** | `VITE_DATA_BACKEND=local` | 닉네임만(임시 프로필, 이 브라우저에만) | 이전과 동일, 로컬 저장 |
| **계정(테스트용)** | `VITE_DATA_BACKEND=supabase` | 이메일 + 비밀번호 + **이메일 인증 필수** | **저장하지 않아요**(4~6단계에서 연결). 쓰기는 "아직 연결되지 않았어요" 오류로 거절되고, 로컬에 몰래 저장하지 않아요 |

- 계정 모드에서도 이 브라우저의 **기존 로컬 기록은 지워지지 않아요**(읽지도, 쓰지도 않을 뿐이에요). 로컬 모드로 돌아가면 그대로 보여요.
- 화면의 안내 상자가 모드에 따라 달라져요: 로컬 = "이 브라우저에만 저장", 계정 = "계정 모드(개발 중)… 지금은 저장되지 않아요".

## 2. 가입 · 로그인 흐름

1. **가입**: 이메일 · 닉네임(2~12자 한글/영문/숫자/_) · 비밀번호(8자 이상, 확인 입력). 닉네임 칸을 벗어나면 서버에 중복을 미리 확인
2. 가입 → **"인증 메일을 보냈어요"** 안내 + **재발송 버튼**(60초에 한 번)
3. 메일의 링크를 누르면 앱으로 돌아와 인증 + 자동 로그인 (PKCE 방식이라 HashRouter와 충돌하지 않아요)
4. **인증 전 로그인 시도**: "이메일 인증이 필요해요" + 같은 재발송 안내
5. 인증을 마친 계정만 로그인 상태로 인정(인증 안 된 세션이 오면 즉시 로그아웃)

### 한글 오류 안내
잘못된 이메일/비밀번호 · 이미 가입된 이메일 · 닉네임 중복 · 약한 비밀번호 · 사용할 수 없는 이메일 · 인증 메일 발송 한도 · 요청 과다 · 인증 링크 만료 · 서버 연결 실패("아무것도 저장되지 않았어요") · 알 수 없는 오류.
메일 링크가 오류로 돌아오면(`#error_code=otp_expired` 등) 라우터가 깨지지 않게 로그인 화면으로 옮겨서 안내해요.

## 3. 비밀번호 · 키 안전

- 비밀번호는 **Supabase Auth 서버로만** 전송돼요. 이 앱은 DB·localStorage·로그 어디에도 저장하지 않고, 로그인/가입 후 입력칸을 비워요.
- 브라우저에는 로그인 **세션 토큰**만 남아요(supabase-js 기본 동작, localStorage). 비밀번호는 남지 않아요.
- 브라우저 설정에 **비밀 키(`sb_secret_…`, `service_role`)가 있으면 연결 자체를 거부**하고 이유를 화면에 보여줘요(점검 스크립트와 같은 규칙).
- Supabase 연결 오류 시 **로컬로 대신 처리하지 않고** 오류를 그대로 보여줘요.

## 4. 직접 확인하는 방법 (실제 이메일 사용)

> 아래는 사용자님이 직접 해야 해요. 가입은 실제 메일이 나가고 한도(SMTP 설정 전에는 시간당 아주 적음)를 쓰니 **본인 이메일 1~2번만** 시도해 주세요.

1. `.env`의 `VITE_DATA_BACKEND=local`을 `VITE_DATA_BACKEND=supabase`로 바꾸고 저장
2. 개발 서버 재시작: `npm run dev` (Ctrl+C 후 다시). 주소는 터미널에 나온 포트
3. **Supabase 대시보드 → Authentication → URL Configuration**의 Redirect URLs에 그 주소가 있는지 확인
   (예: `http://localhost:5174/my-first-website/my-bakery-review/**`)
4. `/#/signup`에서 가입 → 메일의 링크 클릭 → 앱으로 돌아와 로그인되는지 확인
5. 로그아웃 후 `/#/login`에서 이메일·비밀번호로 로그인 / 인증 전 계정은 안내가 나오는지 확인
6. 대시보드 **Authentication → Users**에서 가입한 계정, **Table Editor → profiles**에서 닉네임 행이 생겼는지 확인
7. 확인이 끝나면 `VITE_DATA_BACKEND=local`로 되돌려도 돼요(4단계 연결 전까지 계정 모드는 저장 기능이 꺼져 있어요)

문제가 생기면 화면의 안내 문구(비밀번호·키 제외)를 알려 주세요.

## 5. 자동 검증

| 검증 | 결과 |
|---|---|
| `node supabase/tests/account-repository.test.mjs` | 가짜 Supabase 클라이언트로 38개 시나리오(입력 검증, 가입·로그인·재발송·링크 복귀, 오류 안내, 비밀번호 비노출, 로컬 저장 없음, 비밀 키 감지) |
| 실제 서버 + 브라우저 | 계정 모드 로그인·가입 화면 렌더링, **닉네임 중복 확인(`is_nickname_available`)이 실제 서버에서 동작**, 비밀 키 설정 시 연결 거부 안내, 로컬 모드 변화 없음 |
| 모바일 390px | 로그인·가입·마이페이지 가로 넘침 없음, 누를 곳 36px 이상 |

## 6. 알려진 한계

- **실제 가입·메일·로그인 왕복은 이 자동 검증에 포함되지 않았어요**(계정 생성 필요). 위 4번으로 확인해 주세요.
- **다른 브라우저/기기에서 메일 링크를 열면**(PKCE) 이메일은 인증되지만 자동 로그인은 안 돼요 → "로그인해 주세요" 안내를 보여줘요.
- **비밀번호 재설정**은 이번 단계 범위에 없어요(요청하시면 추가).
- 인증 메일 발송 한도: SMTP를 설정하기 전에는 시간당 매우 적게 나가요(`docs/supabase-setup-guide.md` 3-2).
- 사용자가 `profiles`에 닉네임을 바꾸는 화면은 아직 없어요(권한만 있음).
