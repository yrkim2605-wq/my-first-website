# Supabase 7단계 · 실제 랭킹(명예의 전당) 연동

> 상태: 구현 + 자동 검증 완료 / **0005 적용과 진짜 서버에서의 화면 확인은 사용자 작업 필요**
> 기본값은 여전히 `VITE_DATA_BACKEND=local`(예시 순위표). 기존 표 · 데이터(리뷰, 방문 체크, EXP, 레벨, 도감, 커뮤니티)는 건드리지 않아요.

## 1. 무엇이 바뀌었나요?

| 구분 | 계정 모드 (`VITE_DATA_BACKEND=supabase`) | 로컬 모드 (기본) |
|---|---|---|
| 탭 | **EXP 순위 · 이번 달 리뷰왕 · 리뷰 많은 빵집 · 좋아요 많은 글** (4개) | 예전 5개 탭 (모두 **‘예시 데이터’** 표시) |
| 데이터 | 서버에 저장된 **모든 모험가의 실제 기록** | 코드 속 예시 + 이 브라우저의 기록 순위 |
| 내 순위 | 로그인하면 **상위 10위 밖이어도** “내 순위 N위” 카드 (EXP · 이번 달 리뷰왕) | 내 기록 카드 |
| 데이터가 없을 때 | **빈 상태 화면** (예시 데이터를 섞지 않아요) | — |
| 비로그인 | 순위를 볼 수 있어요 (내 순위 자리에는 로그인 안내) | — |

계정 모드에서 뺀 탭과 이유
- **방문 많은 회원**: 방문 체크는 “나만 보는 체크”(비공개 · 인증 아님)라 순위로 공개하지 않아요.
- **인기빵집 TOP 10 (하트)**: 빵집 하트 기능이 없어요.
- **좋아요 많은 리뷰**: 리뷰 좋아요 기능이 없어요. (대신 6단계로 가능해진 ‘좋아요 많은 글’ 탭을 넣었어요.)

## 2. 순위 규칙 (서버가 계산해요)

순위 번호는 1, 2, 3… **겹치지 않아요.** 동점이면 아래 순서로 가려요.

| 탭 | 기준 | 동점이면 (차례대로) |
|---|---|---|
| EXP 순위 | 누적 EXP (EXP 대상 일지가 1개 이상인 모험가만) | 일지 수 → 먼저 가입한 순 |
| 이번 달 리뷰왕 | **한국 시간 기준 이번 달 1일 0시부터** 남긴 일지 수 | 누적 EXP → 먼저 가입한 순 |
| 리뷰 많은 빵집 | 빵집별 일지 수 | 평균 별점 → 이름순 |
| 좋아요 많은 글 | 글의 좋아요 수 | 댓글 수 → 먼저 쓴 글 순 |

- 이번 달 경계: 이번 달 1일 0시 **정각**의 일지는 이번 달, **1초 전**은 지난달이에요. 고쳐 쓴 일지는 처음 쓴 달로 세요.
- 공개되는 정보: 닉네임 · 레벨 · EXP · 일지/좋아요/댓글 수. **이메일 등 개인 정보는 뷰에 칸 자체가 없어요.**
- 읽기 전용: 로그인하든 안 하든 이 뷰로는 데이터를 **쓰거나 고치거나 지울 수 없어요**(읽기 권한만 부여).

## 3. 0005 마이그레이션 적용 방법 (초보자용)

> 0005는 **‘보기 전용 뷰’ 4개를 추가**해요. 기존 표와 데이터는 건드리지 않고, 여러 번 실행해도 안전해요.
> 0004(댓글 목록 뷰)가 먼저 적용돼 있어야 해요 (이미 적용하셨어요).
> ⚠️ **적용하기 전에는 계정 모드의 명예의 전당이 “순위 기능이 아직 서버에 설정되지 않았어요” 안내를 보여줘요.**
>
> 보너스: 0005는 0004의 `comment_feed` 뷰도 읽기 전용으로 단단히 정리해요(권한을 다시 읽기만 주도록).

1. [Supabase 대시보드](https://supabase.com/dashboard) → 이 프로젝트 → 왼쪽 **SQL Editor**(`</>`)
2. **New query**로 빈 입력창을 열어요.
3. 내 컴퓨터의 `lecture1/my-bakery-review/supabase/migrations/0005_rankings.sql`을 메모장(또는 VS Code)으로 열고 **전체 선택(Ctrl+A) → 복사(Ctrl+C)**
4. SQL Editor 입력창에 **붙여넣기(Ctrl+V)**
5. 오른쪽 아래 초록색 **Run**(또는 Ctrl+Enter)
6. 결과 칸에 **`Success. No rows returned`**가 나오면 성공이에요.
   - 빨간 오류가 나오면 **글자를 그대로 복사해서 알려 주세요.** (`relation "public.user_progress" does not exist`는 0001·0002가, `relation "public.post_feed" does not exist`도 같은 이유예요.)
7. (확인) 새 쿼리에서 아래를 실행해 오류 없이 결과(0줄도 정상)가 나오면 끝이에요.
   ```sql
   select * from public.ranking_exp limit 5;
   select * from public.ranking_monthly_reviews limit 5;
   select * from public.ranking_bakeries limit 5;
   select * from public.ranking_posts limit 5;
   ```

되돌리고 싶다면(보통 필요 없어요): `drop view public.ranking_exp, public.ranking_monthly_reviews, public.ranking_bakeries, public.ranking_posts;` — 기존 데이터에는 영향이 없어요.

## 4. 진짜 서버에서 직접 확인하는 방법

1. `.env`가 `VITE_DATA_BACKEND=supabase`인 상태로 `npm run dev` → `http://localhost:5173/my-first-website/my-bakery-review/#/ranking`
2. **로그인하지 않은 상태**에서: 탭 4개가 보이고 오류 없이 열리는지 (처음엔 ‘비어 있어요’ 화면이 정상이에요), “내 순위” 자리에 로그인 안내가 나오는지
3. 로그인 → 실제 빵집에 **모험 일지**를 남기고 → 명예의 전당 **EXP 순위**에 내 이름 · 레벨 · EXP가 올라오는지, **내 순위 N위** 카드가 보이는지
4. **이번 달 리뷰왕**에 이번 달 일지 수로 올라오는지 (한국 시간 기준)
5. **리뷰 많은 빵집**에 방금 일지를 남긴 빵집이 올라오는지
6. 커뮤니티에서 글에 **좋아요**를 누르면 **좋아요 많은 글** 탭에 올라오고, 글 제목을 누르면 글로 이동하는지
7. (계정이 2개 이상이면) 두 번째 계정으로도 일지를 남겨서 **순서 · 동점 순서**(EXP가 같으면 일지 많은 순 → 먼저 가입한 순)가 맞는지, 로그인을 바꾸면 “(나)” 표시와 내 순위가 바뀌는지
8. 모바일 폭(브라우저 창을 좁히기)에서 시상대가 세로로 쌓이고 글자가 잘리지 않는지

문제가 생기면 화면의 안내 문구(키 제외)를 알려 주세요.

## 5. 자동 검증

| 시험 | 방법 | 결과 |
|---|---|---|
| 랭킹 뷰 · 보안 (진짜 Postgres/PGlite) | `PGLITE_DIR=<pglite 폴더> node supabase/tests/ranking.test.mjs` | 45개 통과 |
| 랭킹 저장소 (가짜 클라이언트) | `node supabase/tests/ranking-repository.test.mjs` | 19개 통과 |
| 기존 서버 규칙 · 보안 | `rls.test.mjs` (+ 리뷰 · 방문 · 계정 · 빵집등록 · 커뮤니티 저장소) | 102 · 37 · 19 · 38 · 42 · 43개 통과 (이전과 동일) |

`ranking.test.mjs`가 확인하는 것
- **빈 상태**: 데이터가 없으면 4개 랭킹 모두 오류 없이 0줄
- **EXP 동점 규칙**: EXP가 같으면 일지 많은 쪽 → 먼저 가입한 쪽 (가입 시각을 바꾸면 순서가 따라 바뀜), 순위 번호는 1부터 겹치지 않음
- **내 순위**: 15위 사용자를 `user_id`로 걸러 가져와도 전체 기준 15위로 나옴 (상위 10위 밖)
- **한국 시간 월 경계**: 이번 달 0시 정각은 포함, 1초 전은 제외, `month_label`이 한국 시간 이번 달
- **빵집 · 글 순위**: 동점일 때 평균 별점 → 이름, 댓글 수 → 먼저 쓴 글 순. 좋아요 취소 · 글 삭제가 순위에 바로 반영
- **공개 범위**: 비로그인도 4개 모두 읽기 가능, 이메일 · 개인정보 칸 없음, 방문 체크는 여전히 비공개
- **읽기 전용**: 비로그인 · 로그인 모두 뷰에 insert/update/delete 불가, 쓰기를 시도해도 원본 데이터 그대로, `anon`/`authenticated`에 SELECT만 부여
- **기존 데이터 불변**: 0005를 적용해도(두 번 실행해도) 기존 표 8개의 행 수와 내용 해시가 그대로
- **일치**: `ranking_exp`의 EXP가 기존 `leaderboard` 뷰와 같음
- 구현을 일부러 틀리게 바꿔 보면(동점 순서 뒤집기, 월 경계 `>=`→`>`) 테스트가 실패하는 것도 확인했어요.

## 6. 알아둘 점

- 순위는 매번 서버에서 계산해요(집계 뷰). 모험가가 수천 명이 되면 느려질 수 있어서, 그때는 캐시용 표(주기적 갱신)를 검토해야 해요.
- 기존 `leaderboard` 뷰는 남겨 뒀어요(앱은 새 `ranking_exp`를 써요).
- 로컬 기록 → 계정 이전 절차는 아직 없어요 (8단계 이후).
