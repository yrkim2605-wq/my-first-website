# Supabase 5단계 · 빵집 도감 · 다녀왔어요(방문 체크) 연동

> 상태: 구현 + 자동 검증 완료 / **진짜 Supabase 서버에서의 방문 체크 확인은 사용자 작업 필요**
> 기본값은 여전히 `VITE_DATA_BACKEND=local`. 로컬 기록은 지우지도 바꾸지도 않아요.

## 1. 빵집 도감 (정리)

- 도감의 "발견 완료" = **내가 모험 일지를 남긴 서로 다른 빵집**이에요 (4단계에서 이미 서버 리뷰에 연결됨).
  - 하루 EXP 상한을 넘어 EXP 없이 저장된 일지도 도감에는 기록돼요.
  - 일지를 지우면 그 빵집의 발견도 회수돼요(재계산 정책).
  - 다른 기기에서 로그인해도 같아요(서버 일지 기준).
- **방문 체크는 도감에 반영되지 않아요**(요구사항). 도감 칩(지역별 발견/전체)과 "더 보기"는 그대로예요.

## 2. 다녀왔어요 (방문 체크)

| 요구 | 구현 |
|---|---|
| 로그인한 사용자별 저장 | `bakery_visits(user_id, bakery_id)` — 기본키가 (사용자, 빵집)이라 중복 불가 |
| 다른 기기에서도 유지 | 서버 저장. 새로고침 · 다른 브라우저에서 로그인해도 보임 |
| 체크 · 취소 | 버튼으로 토글. **서버 저장이 끝난 뒤에** 표시가 바뀌고, 저장 중에는 "저장하는 중…"으로 눌림 방지 |
| 마이페이지 연동 | "다녀왔어요 체크한 빵집" 목록(지도 목록에 없어도 서버에 저장된 이름으로 표시) |
| EXP 없음 | 체크는 EXP · 도감 · 퀘스트에 영향 없음 (서버 테스트로 확인) |
| 방문을 인증한 것처럼 표시하지 않기 | 문구: "나만 보는 체크예요. 실제 방문을 인증하지 않아서 EXP · 도감 · 퀘스트에는 반영되지 않아요" (빵집 상세 · 마이페이지) |
| 본인만 접근 | 내 체크만 읽기 · 쓰기 · 지우기 가능(서버 권한). 다른 사람은 볼 수도 지울 수도 없어요 |
| 이메일 인증 | 인증을 마친 사용자만 체크 가능 |
| 연결 실패 | 로컬에 몰래 저장하지 않고 안내만 표시 ("저장되지 않았어요" 등) |
| 로그인 안 한 상태 | "로그인하면 방문 체크를 남길 수 있어요" 안내(저장하지 않음) |

- **처음 보는 빵집**을 체크하면 리뷰처럼 서버 함수(`register-bakery`)가 카카오로 확인해서 등록한 뒤에 체크돼요(같은 함수, 같은 설정).
- **로컬 모드**는 이전과 똑같아요(`my-bakery-review:visited-real-bakery-ids`에 그대로 저장).

## 3. 진짜 서버에서 직접 확인하는 방법

1. `.env`가 `VITE_DATA_BACKEND=supabase`인 상태로 `npm run dev` (카카오 지도가 보이려면 `localhost:5173`)
2. 로그인 → 빵집 상세 → **다녀왔어요** 클릭
   - 버튼이 잠깐 "저장하는 중…" → "다녀왔어요 ✓"
   - 대시보드 Table Editor → **`bakery_visits`**에 내 `user_id` + 빵집 행, **`bakeries`**에 빵집(처음이었다면)
3. 새로고침 · 다른 브라우저(또는 시크릿 창)에서 같은 계정으로 로그인 → 체크가 유지되는지
4. 마이페이지 **다녀왔어요 체크한 빵집**에 보이는지, **EXP · 도감 숫자는 그대로**인지
5. 다시 눌러 **취소** → 표에서 행이 사라지는지
6. (선택) 다른 계정으로 로그인해서 내 체크가 보이지 않는지

문제가 생기면 화면의 안내 문구(키 제외)를 알려 주세요.

| 로컬 모드 | 이전과 같은 키에 저장, 화면 동작 동일 |

## 5. 알려진 한계

- **진짜 서버에서의 방문 체크는 아직 확인하지 못했어요**(위 3번).
- 체크한 빵집이 지도 목록(카카오 검색 결과)에 없으면 사진은 기본 사진으로 보여요.
- 목록은 내 체크 최대 1,000개까지 불러와요.
- 기존 로컬 방문 체크의 계정 이전은 포함하지 않았어요(로컬 기록은 그대로 보존).
